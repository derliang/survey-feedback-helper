## 結論與優先序

- **P0（行為核對後再改）**：原文可能使人誤解資料會被保留／刪除、留言會對誰顯示、個資是否已遮蔽、雲端是否覆蓋，或選課／票選結果是否確定。修改前必須對照實際實作、設計裁示與測試。
- **P1（優先修文案）**：讓教師知道下一步要做什麼、按鈕會造成什麼結果、資料來源與支援格式。
- **P2（最後潤飾）**：沒有實際語意風險的措辭一致性與精簡。

## Claude 實作與比對方法

1. 先讀 `CLAUDE.md`、`docs/design/DESIGN.md`、`todo.md` 及相關裁示。本文只提供**文字提案**，不覆蓋已定案的設計規範；衝突時先回報使用者確認。
2. 以「**檔案＋約略行號＋完整原文**」定位。行號是建立本文件當下的 `main`，日後程式增刪後可能位移。**不可對整個專案做全域搜尋／取代**：例如「下載」「採用」「重新開始」在多處出現，實作應以物件鍵、相鄰語境或 JSX 元件定位，每筆逐項確認。
3. 動態文字中的 `${name}`、`${n}`、`{姓名}` 為**字面佔位符**，須保留變數、引號與格式化行為；不可複製本文的 Markdown 反引號進程式。
4. 以文字是否與**現有功能**吻合為第一關；P0 並非可直接替換，若不吻合須保留原文並在待辦中標記「需決策」，不得偷偷改程式功能配合文案。
5. 編輯器 `src/ui/editor/*.tsx` 與少部分 `src/ui/views/*.tsx` 的字串仍直接寫死，建議先集中至單一文案管理層再改（不得影響編輯器範本資料結構、TypeScript 欄位鍵、匯出相容性）。
6. `src/ui/strings.en.ts` 與 `src/ui/strings.en.more.ts` 有英文對照；改動繁中時同步檢查英文介面及測試，不可造成兩語內容互相矛盾。外部 Google 介面字樣與隱私政策以實際核對／規範優先。
7. 改程式走分支、`npm run ci` 測試、PR、調度員審核；僅文件可依現行 `CLAUDE.md` 直接進 `main`。此次不執行上線發布。

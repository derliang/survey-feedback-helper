## 二、已驗證或可直接從程式確認的問題

### AUD-01 [P0／D] 分組結果過期判斷漏掉名額、志願與規則變更

- **來源**：`src/app/course-app.ts:253-258` 的 `resultStale()`、`src/ui/views/CourseView.tsx:546,687-697`。
- **模擬操作**：先分配學生 0 到「A 課」，名額為 1；接著將 A 課名額改為 0，但學生列表仍是同一個 ID。另一案例是把該學生的志願從 A 改為 B，ID 仍不變。
- **期望**：既有結果應標示需重新分配，必要時封鎖輸出。
- **實際 D 結果**：兩個案例 `resultStale()` 都回傳 `false`。程式只檢查 `result.length` 和申請者 ID 集合，沒有比對課程名額、課程清單、志願內容、優先名單、合併對照或抽籤種子。
- **風險／建議**：結果可能與新規則不一致；用「分配輸入快照／穩定雜湊」校驗結果，不以學生數或 ID 作為唯一依據；更動重要條件時標記失效，加入邊界測試。

### AUD-02 [P0／C] 顯示「結果已過期」仍允許前往輸出並下載

- **來源**：`src/ui/views/CourseView.tsx:684-700,799-805`、`src/ui/views/CourseOutput.tsx:24-46,48-65,121-126`。
- **模擬步驟**：在已產生分配後增減學生，導致 `resultStale()` 為真；不按重新分配，直接按「確認，下一步：輸出」，再按「產生並下載」。
- **程式結果**：結果畫面有過期警示和重新分配鈕，但「下一步：輸出」未依 `stale` 停用；輸出頁僅確認有 `course.result`，未呼叫 `resultStale()` 重新檢查；下載入口也未依結果過期停用。
- **風險／建議**：把過期結果下載成正式分組名單。至少在輸出頁再次檢查並阻擋或要求明示重算，不可只靠前頁警語。

### AUD-03 [P0／D] 未選資料夾先進分組，之後授權無法讀回同問卷舊存檔

- **來源**：`src/app/store.ts:643-659`，`courseLoadedFor` 只有問卷 ID，沒有資料夾狀態。
- **模擬操作**：開啟問卷 S（未授權資料夾）→ 執行 `loadCourse()` → 這時才授權資料夾 → 再進同一問卷的分配頁。
- **實際 D 結果**：第二次呼叫直接 return，模擬讀取計數為 **0**，存在資料夾中的分組結果未被載入。
- **建議**：將儲存來源及權限狀態納入載入快取鍵，或在選取／重新授權資料夾時清理快取並重新讀取；處理既有本次變更與舊存檔衝突。

### AUD-04 [P0／D] 審稿進度同樣無法在稍後取得資料夾權限後重新載入

- **來源**：`src/app/store.ts:585-599` 的 `loadReview()`。
- **模擬操作**：未選資料夾時進入審稿（建立空白審稿狀態）→ 選取有舊審稿紀錄的資料夾 → 返回同一問卷的審稿或輸出。
- **實際 D 結果**：`review?.surveyId === session.surveyId` 命中後直接 return，讀檔計數 **0**，仍停留在空白進度。
- **建議**：重新授權時檢查有無已儲存審稿紀錄並提供明確的「讀回／保留本次內容」衝突處理，避免誤蓋舊進度。

### AUD-05 [P0／D] 分組存檔慢載時切換問卷，前一份的結果可能寫進新問卷

- **來源**：`src/app/store.ts:646-658`，讀檔 `await` 後直接 `setSession({ course: ... })`；`setSession` 更新當下的 session。
- **動態模擬**：問卷 A 開始讀取 `選課分組-A.json`，在檔案回傳前切換至問卷 B；再讓 A 的讀檔完成。
- **實際 D 結果**：目前問卷為 **B**，但 B 的 `course.result` 被寫入 **A 的學生與課程結果**。
- **建議**：每次非同步讀檔完成前，核對仍是原 survey ID／載入序號；切換問卷取消或忽略舊請求。此項高於一般 UI 問題。

### AUD-06 [P0／D] 審稿非同步讀檔存在相同跨問卷競態

- **來源**：`src/app/store.ts:586-599`。
- **動態模擬**：讀取 A 的審稿進度尚未回傳時切換為 B，接著 A 回傳。
- **實際 D 結果**：`session.surveyId` 是 B，但 `review.surveyId` 是 A；狀態暫時錯置。若有後續寫入或渲染，可能造成進度混亂。
- **建議**：與 AUD-05 同樣加入請求世代檢查／取消機制，並測試切換及重入條件。

### AUD-07 [P1／D] 志願清理會重新編號，回報的「第幾志願」不一定等於原始填答

- **來源**：`src/core/course.ts:43-54,61-101` 的 `cleanPrefs()`／`allocate()`。
- **模擬操作**：學生原始輸入 `[A, A, B]`；A 沒有名額、B 有 1 個名額。
- **實際 D 結果**：清理後為 `[A,B]`，分到 B 時 `rank = 2`；原始表單 B 卻位於第 **3** 志願。另以 `[不存在的 X, B]` 對單一 B 課測試，B 會被顯示為第 1 志願（原本是第 2）。
- **建議**：保留原始志願欄索引作為分配後的顯示名次，清理無效／重複選項只能影響運算順序，不能悄悄改掉學生原填志願；須明確訂定重複志願的公平處理規則。

### AUD-08 [P1／D] 名額解析接受超出安全整數範圍甚至 Infinity

- **來源**：`src/app/course-app.ts:136-140` 的 `parseCount()`、`src/ui/views/CourseView.tsx:45-58`。
- **動態模擬**：輸入 73 位數整數，回傳約 `1e73` 且 `Number.isSafeInteger()=false`；輸入 400 位數字「1」，解析為 `Infinity`，但函式不回傳 `null`。
- **建議**：限制為非負、有限、安全整數並設定符合學校現實的合理上限；欄位旁顯示明確的驗證錯誤，不讓異常名額進入抽籤或統計。

### AUD-09 [P0／D] 同班同名、不同座號的學生可能被當成重複填答

- **來源**：`src/core/check.ts:22-49` 的 `personKey()`／`findDuplicates()`。
- **動態模擬**：兩筆回覆皆為「高三溫、王小明」，座號分別 1 和 22。
- **實際 D 結果**：被歸入**同一重複群組** `高三溫|王小明`，`ids=[1,2]`；不同班級的同姓名則未合併。
- **風險／建議**：同名並不必然同一人，若教師選擇「只保留一份」，可能錯刪有效回覆。除姓名外需利用已確認的名單身分、座號及比對結果；存疑時只標「可能重複」，勿預設為可合併。

### AUD-10 [P1／C] 直接讀取 Google 試算表仍顯示來源為 Excel

- **來源**：`src/app/store.ts:378-381,388-447`；`openSurveyTable()` 共用 `startSession()`，其 `sourceLabel` 固定是「Excel 檔」。
- **模擬流程**：首頁從 Google 開啟試算表 → 成功讀取 → 進入「準備資料」查看來源資訊。
- **程式結果**：即使來源是 Google，`session.sourceLabel` 仍寫「Excel 檔」；`src/ui/views/Prepare.tsx:40` 會顯示該標籤。
- **建議**：依來源區分 Excel／CSV／Google 試算表；不得只改畫面文案而留下錯誤的來源資料。

### AUD-11 [P0／C] 對外回饋單的「老師評語」不在個資確認預覽內

- **來源**：`src/app/output.ts:76-96` 會將 `review.teacher[t.key]` 放入 `PersonalFeedbackInput.teacherComment`；`src/ui/views/OutputView.tsx:141-146,405-435` 的安全預覽只列 `p.comments`，未列 `p.input.teacherComment`；`src/ui/strings.ts` 說明老師評語會放在回饋單。
- **模擬情境**：老師填入包含其他學生真實姓名的「老師評語」→ 選學生版或家長版 → 完成留言預覽確認 → 產生使用老師評語變數的回饋單。
- **程式路徑結論**：對外回饋單的模型可包含老師評語，但確認清單及確認簽章不檢查該欄。正式模板如何呈現須以輸出測試再確認。
- **建議**：個資確認預覽應涵蓋**全部即將輸出的自由文字**（同學留言、老師評語及可編輯模板文字）；老師評語或模板內容改變時應讓確認失效。

### AUD-12 [P1／C] 設定頁「返回」固定跳回準備資料，並非原來頁面

- **來源**：`src/ui/views/Misc.tsx:106-109`，`onClick={() => go(st.session ? 'prepare' : 'home')}`。
- **模擬流程**：從「輸出」進設定 → 按「上一步」；從編輯器或統計進設定也同樣測試。
- **程式結果**：只要有問卷，皆回到「準備資料」，不會回到來源頁；容易中斷工作脈絡。
- **建議**：記住來源頁／副頁及捲動位置，或把按鈕改為語意準確的「返回準備資料」。

### AUD-13 [P2／C] 選檔器允許選舊版 .xls，但實際明確拒絕讀取

- **來源**：`src/ui/views/Home.tsx:18-20,171-180` 的 `SURVEY_ACCEPT` 包含 `.xls`，`src/app/load.ts:46-54` 明確把 `.xls` 視為 `oldExcel` 錯誤。
- **模擬流程**：從首頁選擇舊版 `.xls`，檔案選擇器允許，但讀入後必定顯示不能讀。
- **建議**：移除 `.xls` 支援宣示，或提前標示「舊版 Excel 需先另存 .xlsx」，避免無效操作。

### AUD-14 [P0／C] 分組存檔讀取失敗時直接以空白狀態開始，可能與舊檔衝突

- **來源**：`src/app/store.ts:650-656` 與 `src/app/store.ts:679-685`。
- **模擬流程**：選課分組存檔已存在但損毀／讀取權限不足 → 系統顯示「已從空白開始」→ 教師重新設定名額 → 自動寫回相同檔名。
- **程式路徑結論**：讀取失敗後沒有採保護性唯讀狀態或先備份損毀檔的機制；只要後續修改，會嘗試覆寫同檔名。
- **建議**：讀檔失敗後停止自動覆寫同名舊資料，提供「另存一份」「重試」「確認取代」等明確處理方式。審稿進度類似情境一併檢查。

### AUD-15 [P1／H] 「固定結果」只能防止一種重抽途徑，按鈕名稱可能誤導

- **來源**：`src/ui/views/CourseView.tsx:723-728,849-855`。
- **觀察**：「固定結果」只讓結果頁「重新抽籤」按鈕停用；返回名額規則頁仍可按「重新分配」，手動移動學生亦未因固定而全數鎖定。
- **建議**：釐清固定結果的產品定義：是只固定抽籤種子，還是鎖定最終分組？若只阻擋重抽，按鈕文字應寫「鎖定本次抽籤（仍可手動調整）」等；若定義為最終鎖定，須全面限制有關操作。此項**待使用者裁示**，勿自行改行為。

### AUD-16 [P1／H] 問卷載入與錯誤提示缺少一致的「如何恢復」路徑

- **來源**：`src/ui/App.tsx:42-55`、`src/app/store.ts:367-376` 及 `src/ui/strings.ts`。
- **觀察**：各式錯誤多以頂部提示顯示，主操作可能仍保留原狀；不同檔案格式、空白資料、Google 讀取錯誤的下一步指引不一致。
- **建議**：錯誤訊息固定含「發生什麼、資料有無改變、如何重試」，提供直接的重新選檔或返回動作；以 Playwright 測每一種失敗路線。

### AUD-17 [P1／H] 編輯器文字分散，部分操作影響範圍不易判斷

- **來源**：`src/ui/editor/EditorView.tsx`、`src/ui/editor/Panels.tsx`、`src/ui/editor/Preview.tsx`。
- **觀察**：全班範本、個別學生版本、教師／學生／家長輸出版本在介面上並列；「複製」「還原」「刪除」等按鈕的操作範圍不一定立即清楚。
- **建議**：對高風險操作顯示目前編輯範圍與是否能復原，並在小螢幕以說明文和對應上下文區分。需由設計員依既有規範設計，不擅自調整 UI 架構。

### AUD-18 [P1／H] 帳號登入與雲端備份兩個目的容易混淆

- **來源**：`src/ui/views/GoogleConnect.tsx`、`src/ui/views/CloudBackup.tsx`、`src/ui/strings.ts`。
- **觀察**：教師為讀取 Google 試算表登入時，同時會看到設定檔自動備份選項，容易誤認登入即同意備份。
- **建議**：明確標示「讀取問卷」與「備份含學生名單的設定檔」為兩個決策；不改預設關閉或已定案的確認規則。與先前全站文案 V2 對照表整併，避免重複 Issue。

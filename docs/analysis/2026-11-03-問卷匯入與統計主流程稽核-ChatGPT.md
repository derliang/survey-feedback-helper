## 檢查目標

正常教師工作：選擇 Google 表單回覆試算表、Excel、CSV／TSV → 系統辨識題目類型與對應欄位 → 檢查重複／無效資料 → 計算人數、平均、分布與留言 → 檢視與輸出 Excel、PDF 或 Word。這份報告只列可能讓此流程**失敗、算錯、誤導、難以恢復**的問題。選課志願分配、名額、抽籤等不在本次稽核範圍，沒有列入修復待辦。

## 問題與可重現測試

### SUR-01【P0／D】第一張工作表只有說明，第二張才有問卷回覆：程式回報空檔

- **檔案**：`src/app/load.ts:37-60`。
- **輸入**：XLSX 工作表 1「說明」僅有一列欄名「使用說明」；工作表 2「問卷回覆」有欄名「姓名、分數」與兩筆學生回覆。
- **隔離模擬**：`tableFromFile()` 選第一個 `headers.length > 0` 的工作表，最後因 `table.rows.length===0` 拋出 `LoadError('empty')`；完全沒有嘗試第二張。
- **預期**：優先選有有效資料的回應工作表，或讓教師選工作表；第一張有說明不應阻止分析後面資料。
- **建議**：篩選含表頭與資料列的工作表，對多張有效工作表提供選擇。補 XLSX 多工作表整合測試。

### SUR-02【P0／D】TSV 標題內有逗號，分隔符偵測錯誤，導致欄位拆壞

- **檔案**：`src/app/load.ts:26-30,38-45`，`src/core/table.ts:15-55`。
- **輸入**（以 Tab 分欄，第二欄標題與內容含引號包住的逗號）：`姓名\t"你最喜歡的活動,原因,建議"\n王甲\t"課程,時間安排好"`。
- **隔離模擬**：`guessDelimiter()` 回傳 **逗號**，隨後 `parseCsv()` 將表頭錯拆為 `["姓名\\t\\\"你最喜歡的活動","原因","建議\\\""]` 的三欄形式，與原本兩欄不符。
- **預期**：辨識 Tab（而非計算引號內的逗號），保留問卷題目與作答內容。
- **建議**：偵測時考慮 RFC 4180 引號範圍與多行一致性；`.tsv` 優先使用 Tab；加入上述資料測試。

### SUR-03【P0／D】評分題只有一筆非數字錯字，整欄可能被誤分類為選擇題

- **檔案**：`src/app/columns.ts:52-89`。
- **輸入**：無可辨識題型關鍵字的欄名，內容 `[5,4,3,2,4,5,3,4,2,"五分"]`（9 筆有效評分與 1 筆錯字）。
- **隔離模擬**：`guessByContent()` 回傳 **`{role:"choice",confirm:true}`**，不是 score。原因是分數檢測要求所有值均能解析為數字（`nums.every`）；一筆非數字讓它轉入選項偵測。
- **風險**：該題不會得到應有的平均、有效人數與無效分數檢查，結果可能直接錯誤。
- **建議**：利用有效分數比例判斷並標示「評分題（有異常資料待確認）」；改以單筆錯字留給資料檢查處理；加 9／10、8／10、文字混入等測試。

### SUR-04【P1／D】短句型開放題可能被歸類「忽略」而不進報告

- **檔案**：`src/app/columns.ts:52-89`。
- **輸入**：無明確題型關鍵字的欄名，10 筆短且多樣的文字答覆，如「好、普通、不錯、待加強、有收穫、值得、改善、很棒、還好、清楚」。
- **隔離模擬**：`guessByContent()` 回傳 `null`；後續 `analyzeColumns()` 預設 `role='ignore'`、`confirm=false`。
- **預期**：可能是開放題或選項題時應提示教師確認，不能默默當作不需分析。
- **建議**：未辨識欄位集中於顯眼的「待分類」清單，並在完成欄位對應前提示資料可能未被納入。須依現有設計規範處理。

### SUR-05【P0／D】單選內容含頓號，被自動當作複選題

- **檔案**：`src/app/analysis.ts:99-129`、`src/core/survey.ts:8-28`。
- **輸入**：五筆單選回覆 `["人文、社會","自然","自然","自然","自然"]`，其中「人文、社會」是**一個完整選項名稱**。
- **隔離模擬**：`looksMulti()` 回傳 `true`，因一筆含頓號占 20% 達到門檻，`splitMulti()` 之後可能將它拆成「人文」「社會」兩個答案。
- **預期**：不能只因選項名稱有標點就自動判定複選題，更不能悄悄拆分已完整的一個選項。
- **建議**：採用可信的題型元資料或已確認選項集合；沒有依據時請教師確認，避免自動拆分。必須有單選含頓號、真正複選、選項帶逗號三種測試。

### SUR-06【P1／D】1～5 分問卷混入一筆 0，整份量表可能被判為 0～10

- **檔案**：`src/app/columns.ts:208-223`。
- **輸入**：量表題作答 `[5,4,3,2,0]`；原問卷設計是 1～5 分，但 0 是輸入異常。
- **隔離模擬**：`detectScale()` 回傳 `{min:0,max:10}`；0 便可能被納入有效分數，導致統計與教師原問卷設計不符。
- **預期**：依來源量表設定或提示教師確認，不能從極端的單筆異常值直接擴張分數範圍。
- **建議**：在正式統計前要求確認量表上下限；顯示推斷依據及異常分數，避免個別錯字被合法化。

### SUR-07【P0／D】同班同姓名不同座號：系統仍歸類重複填答

- **檔案**：`src/core/check.ts:22-49`、`src/ui/views/CheckView.tsx:23-46`。
- **輸入**：兩份回覆均為「三年溫班、王小明」，座號分別為 1 與 16。
- **隔離模擬**：`findDuplicates()` 回傳一個重複群組，含兩筆 ID；畫面提供「只留第一份／只留最後一份」等排除操作。
- **風險**：把兩位同姓名學生的合法填答當作重複，教師可能因此排除有效資料、改變統計。
- **建議**：利用座號與名單已確認的身分辨識；只有姓名一致但座號不同時應標「疑似重複、需核對」，不能直接建議刪除。

### SUR-08【P1／C】Google 試算表直接讀入，仍顯示資料來源是「Excel 檔」

- **檔案**：`src/app/store.ts:378-381,388-447`、`src/ui/views/Prepare.tsx:38-42`。
- **程式路徑**：`openSurveyTable()`（Google 路徑）呼叫 `startSession()`；`startSession()` 的 `sourceLabel` 固定為「Excel 檔」。
- **預期**：Excel、CSV／TSV、Google 試算表應有正確來源名稱，以利教師確認目前分析的是哪一份回覆。
- **建議**：讓資料來源成為明確參數；調整標籤但不改匯入與統計本身行為。

### SUR-09【P0／C】學生／家長版預覽只核對同學留言，未涵蓋可能輸出的教師評語

- **檔案**：`src/app/output.ts:79-98`、`src/ui/views/OutputView.tsx:140-146,405-435`。
- **程式路徑**：輸出模型包含 `teacherComment`；預覽清單與確認簽章僅列 `p.comments`。
- **風險**：教師評語可能含未預期公開的人名或個資，使用者按「已逐則看過」並未檢查該欄。
- **建議**：對外輸出的**所有自由文字**都應在相同確認流程覆核；更動教師評語時需重新確認。確切模板顯示仍應以 PDF／Word 實測確認。

### SUR-10【P1／C】選檔器顯示可選 .xls，但讀取器明確不支援

- **檔案**：`src/ui/views/Home.tsx:17-20,171-180`、`src/app/load.ts:46-54`。
- **現象**：檔案篩選條件包含 `.xls`，實際上傳卻一定丟出 `oldExcel` 錯誤。
- **建議**：選檔器不標示不支援格式，或提前用一句話提示「舊版 Excel 請先另存為 .xlsx」。

## 對 Claude 的最小可驗收待辦

1. **匯入正確性（最先）**：用虛構 2 工作表 XLSX、含逗號的 TSV、錯誤副檔名測試；每個檔案都要核對「讀到的工作表、欄數、列數、題目名稱、前後一致」。
2. **欄位辨識／資料品質**：使用混入 1 筆文字的評分欄、10 筆短句開放題、同班同名不同座號；確認未納入統計的欄位或列都有可見提醒，不能悄悄略過。
3. **統計計算**：分別測 1～5 量表帶 0 異常、單選選項含逗號／頓號、真正複選，逐題核對有效樣本數、平均、分布、空白數及輸出數字。
4. **輸出／個資**：以相同虛構資料檢查畫面分析、Excel、Word 與 PDF 是否一致；學生／家長版需核對教師評語、留言與去識別提示。
5. **介面復原與操作**：錯檔、空表、未知欄位、待確認資料、輸出失敗後可重新上傳或修正；桌機／平板／手機驗證後才視為通過。
6. **依規範落地**：不改功能目標或原有設計裁示；程式變更走分支與 PR，執行 `npm run ci`、記錄通過證據。**本報告是問題清單，非修正授權。**

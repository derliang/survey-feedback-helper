# 決定記錄：產品範圍與技術決定（2026-10-30）

> 寫給沒看過這段對話的後來者。

## 背景

使用者（老師）要一個放在 GitHub Pages 的網頁程式「問卷回饋小幫手」，讓老師連上網頁就能開啟問卷結果、統計，並輸出班級總表與給學生的個人回饋單。經過一輪討論後定案。

## 已定案的決定

| 項目 | 決定 | 原因 |
|---|---|---|
| 架構 | 純前端、無後端，部署於 GitHub Pages | 免維運；學生資料不離開老師的電腦 |
| 雲端硬碟 | 只做 Google 雲端硬碟，排在 v0.4；第一版不做 OneDrive | 學校多用 Google 表單；兩套授權工作量約增 40% |
| 問卷來源 | Google 表單匯出的 xlsx／csv，也可讀雲端回覆試算表 | 格式固定、最好辨識 |
| PDF | 瀏覽器列印轉 PDF，版面以 HTML/CSS 控制；Word 與 xlsx 由程式產生 | 中文字型自動用系統字型、版面最精美；避免內嵌中文字型造成檔案過大 |
| 批次個人回饋單 | 全班排成一份連續 PDF，每人一頁分頁；Word 版可打包 zip | 列印轉 PDF 一次只存一份 |
| 分階段 | v0.1 本機核心 → v0.2 個人回饋單與設計系統 → v0.3 設定與進階統計 → v0.4 Google 雲端硬碟 → v1.0 PWA 與完整測試 | 先把核心與正確性做穩 |
| 功能範圍 | 使用者要求「全部納入」：強烈建議、建議、可以晚點再說三級全做，見 [feature-blueprint.md](../feature-blueprint.md) | 依分級排進版本，晚點再說的排 v0.3～v1.0，不擠掉核心 |
| 授權 | **GPL-3.0** | 使用者選擇；防止被改成封閉商品。學校自己內部修改不發布不受影響 |
| Repo | `derliang/survey-feedback-helper`，公開 | 使用者指定 |
| 資料不落地 | 原始問卷資料只在記憶體，關頁即清；瀏覽器只存設定 | 教師個資保護，為產品原則 |
| 老師審稿範圍 | v0.2 先做手動勾選與老師評語，字詞提醒只提供可自訂關鍵字清單，不做智慧判斷 | 控制 v0.2 範圍 |

## 被否決或延後的選項

- **OneDrive／Microsoft Forms**：延後，視需求在 v1.0 後再評估。
- **程式直接產生 PDF**：否決，需內嵌中文字型，檔案大、版面受限。
- **使用 AI 分析開放題留言**：否決，需外部服務會讓學生資料離開本機；改用離線分組與關鍵詞頻率。
- **不指定授權**：否決，預設保留所有權利，與公開分享的目的不符。

## 待確認（尚未決定）

- **技術選型**：我的建議是純前端、盡量免建置（原生 JS 或輕量框架）。尚未定案，開工 v0.1 前須寫入決定記錄。
- **第三方套件**：預計需要 xlsx 讀寫、docx 產生等套件；多為 MIT／Apache-2.0，可併入 GPL-3.0，引入時逐一核對並登錄於 `docs/third-party.md`。
- **設計系統**：由設計員建立，尚未開工。
- **Google OAuth 用戶端 ID**：需使用者本人以 Google 帳號建立，v0.4 前處理。

## 未實測的風險

- File System Access API 在 Safari／Firefox 不可用，已規劃退回做法，尚未實測各瀏覽器行為。
- 列印轉 PDF 在大量學生（全班連續分頁）時的版面穩定度尚未驗證，v0.2 要實測。

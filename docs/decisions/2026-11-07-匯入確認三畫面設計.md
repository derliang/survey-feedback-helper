## 背景

2026-11-03 第三方稽核（[問卷匯入與統計主流程稽核](../analysis/2026-11-03-問卷匯入與統計主流程稽核-ChatGPT.md)）的 SUR-01、SUR-04、SUR-06，程式端已由 PR #65 修正並隨 v0.2.8 發布，但三個需要使用者介面的部分依硬規則 11（所有設計稿由設計員設計）未做：

| 稽核項 | 缺的畫面 | 程式現況（`src/app/load.ts`、`columns.ts`、`MappingView.tsx`） |
|---|---|---|
| SUR-04 | 「待分類」集中清單 | 猜不出題型但有內容的欄標 `role='ignore'`＋`confirm=true`，掉進列表最下面收合的「沒有使用的欄」；頂端寫「N 欄請確認」但找不到；按「完成對應」時 `finish()` 把全部 `confirm` 清成 `false`，等於悄悄略過 |
| SUR-06 | 量表上下限確認 | 只有列表最下面一個「量表範圍」分段（1～5／0～10）；`finish()` 又用 `detectScale()` 重算 `scale`，老師手動選的會被蓋掉 |
| SUR-01 | 多工作表選擇 | `tableFromFile()` 取第一張「有欄名也有資料列」的；多張都有資料時沒給老師選，也沒顯示用了哪一張 |

## 結論

| 項目 | 決定 | 原因／被否決的選項 |
|---|---|---|
| 三畫面的共通做法 | 沿用既有元件，**不新增元件**；要老師決定的事放在警示外框卡，決定前「完成對應」停用並在旁邊寫原因 | 另做專屬步驟頁：老師流程多一步；全部塞進底部彈出面板：資訊多（長條、預覽）放不下，也看不到列表 |
| 待分類位置 | 欄位對應列表**最上面**的警示卡，一欄一組、直接給籌碼（選擇題、開放意見、評分、不使用）＋「其他類型…」開既有面板；分類後移到卡底「已處理」可反悔；剩 2 欄以上有「其餘 N 欄都不使用」 | 維持一欄一欄點開既有欄位類型面板：3 欄以上要開關很多次，且沒有集中提示；單獨一個「待分類」頁籤或步驟：老師可能不點進去；籌碼改用分段控制：沒有「尚未選」的狀態 |
| 待分類的閘門 | 仍有待分類欄時「完成對應」**停用**，旁邊寫「還有 N 欄待分類，分完才能往下」；「其餘 N 欄都不使用」讓有雜訊欄的老師一鍵過關 | 見〈待使用者決定 1〉 |
| 量表何時問 | 只在有疑慮時：①判定 1～5 但有零星 0 分；②最大值 ≤5 且 0 分不零星（判成 0～10）。純 1～5 或有 6 分以上的 0～10 不問，維持現狀分段 | 每次都問：多數問卷沒疑慮，變成每次多一關；永遠只顯示分段不提醒：就是現在的問題 |
| 量表畫面內容 | 疑點說明＋「各分數有幾筆」長條（可疑的用警示色加「可疑」標籤）＋異常分數在哪一欄＋兩張單選卡，每張寫「選了會怎麼算」；**套用到全部評分欄**（`Session.scale` 是全問卷一個範圍） | 逐欄各問一次：資料模型沒有逐欄量表；只問「1～5 還是 0～10」不給證據：老師無從判斷 |
| 量表預選 | **不預選**，「建議」標籤標出系統判斷，老師要點一下 | 見〈待使用者決定 2〉 |
| 工作表何時問 | 2 張以上「有欄名也有資料列」才問；完全空的不列出，用一行提示說「已略過」；只有 1 張有資料時流程不變 | 只擋全空的：「使用說明」頁有幾列字也算有資料，仍會選錯；每個 Excel 都問：單張檔多一步 |
| 工作表畫面 | 單選卡（名稱、筆數、前幾欄），**預選「建議」（資料列最多者）**；平板、桌機左清單右預覽表，手機縮成「前幾欄」一行 | 只列名稱：老師分不出哪張是回覆；合併多張一起分析：欄位與列對不起來，超出範圍 |
| 事後更換 | 準備資料頁頭顯示「工作表：…／這個檔共 N 張有資料」＋「更換工作表」，回到同一頁（標「目前使用」，警示「更換後重新判斷欄位，已做的對應不保留；學生名單不受影響」） | 選錯只能重新開始：已做的設定全丟，老師會怕選；更換時保留舊對應：不同工作表欄位不同，對應會錯位 |
| 為什麼量表不預選、工作表預選 | 選錯工作表老師一看資料就知道，而且可更換；選錯量表會**悄悄改變平均**，畫面上看不出來 | 兩者一律預選：量表錯了沒人發現；一律不預選：工作表多一次必要點擊 |

## 待使用者決定（調度員統一用問題卡問）

1. **待分類要不要擋下「完成對應」**。我的建議：**硬擋＋「其餘 N 欄都不使用」一鍵**（本稿畫法）。另一個選項：軟擋（可按，按下跳確認「還有 N 欄沒分類，會當作不使用」）；缺點是老師按習慣性略過，回到「悄悄略過」的老問題。
2. **量表要不要預選建議**。我的建議：**不預選**（本稿畫法，多一次點擊換不漏看）。另一個選項：預選建議、只在卡片上標「已依資料判斷為 1～5，確認」；缺點是老師可能沒看就按下一步。
3. **多張有資料的工作表要不要每次都問**。我的建議：**每次都問**（本稿畫法，預選建議、一次點擊）。另一個選項：資料列明顯最多、其餘像說明頁時自動採用並在準備資料頁標示可更換，只有猜不準才問；缺點是「猜得準」的規則要另外定、猜錯時老師不會發現。

## 施工注意（給實作者，不是設計裁示）

- **老師確認過的量表不得被 `finish()` 的 `detectScale()` 覆蓋**（現況會蓋掉），需記錄「已確認」狀態；有疑慮的判斷只在尚未確認時重算。
- `countToConfirm` 目前把待分類欄也算進「N 欄請確認」；本設計把待分類另列，「N 欄請確認」不含它們。
- 待分類欄在老師處理前要保持 `role='ignore'`＋待分類標記，**列表與準備資料列副標才寫得出「N 欄待分類」**；「不使用」是老師明確選的，才算已處理。
- 疑慮門檻以現有 `detectScale()` 為準：判定 1～5 且 `zeros ≤2` 且 `<5%`；或 `max ≤5` 而 `min===0` 且 0 不零星。實作時請抽成函式回傳「為何有疑慮」，畫面才寫得出「大多數在 1～5、有 1 筆 0 分」。
- 「建議」那張工作表＝資料列最多者，不另做更複雜的猜測；若施工者想加「欄名含時間戳記」等規則，先回報。
- 更換工作表後欄位對應、資料檢查處理重來、學生名單（存在資料夾）不受影響，是**設計意圖**；實際哪些狀態被清掉，施工時對照 `store.ts` 的 session 欄位逐項確認。
- 字串表在 DESIGN.md 5.30，可直接放進 `src/ui/strings.ts`；新增字串後 e2e 的文字斷言（若有）要同步。

# 輸出器與字型管線（2026-11-01）

> 寫給沒看過討論的後來者。承接 [原型驗證結果](2026-10-30-原型驗證結果.md)，把原型正式化。程式在 `src/export/`、`src/fonts/`，分支 `export-fonts`。

## 做了什麼

- **文件模型**（`src/export/model.ts`）：可序列化成 JSON 的區塊清單（標題、文字、條列、表格、圖片），變數替換規則 `[^{}]+`（中文變數可用）；表格可標「強調列」（平均列）；頁面可為 A4 直式或橫式。
- **預設範本**（`templates.ts`）：個人回饋單（含平均列）、班級總表（橫式、含班級平均列）。輸入是一般資料結構，**不直接相依 `src/core`**；與統計結果的接線留給介面。
- **輸出器**：PDF（`pdf.ts`，自己排版與換行）、Word（`docx.ts`）、xlsx（`xlsx.ts`，自寫 fflate）、批次 zip（`batch.ts`，每位學生一個 PDF）。全部經 `src/export/index.ts` 的 `loadXxx()` 動態載入；首頁 gzip 實測 5.6 KB。
- **字型管線**（`src/fonts/`）：自包 HarfBuzz 子集化（`subset.ts`，直接用 harfbuzzjs wasm）；字型 WOFF2 → `woff2-encoder` 解壓一次（`loader.ts` 快取）；`public/sw.js` 快取字型與 wasm；`word-fonts.ts` 放 Word 字型退讓與說明文字。

## 決定與原因

1. **字型用 Noto Sans TC 可變字型單一檔（WOFF2 5.43 MB），不分一般／粗體兩檔**。原因：這台沒有靜態字重檔，只有 `NotoSansTC-VF.ttf`；HarfBuzz 子集化時可固定 `wght`（400／700）輸出靜態字型，結果與靜態字重等價（視覺測試與完整字型逐像素比對）。大小與原先估計的兩檔合計（5.6 MB）相當，少一次下載。
2. **WOFF2 解壓用 `woff2-encoder`，不用 `wawoff2`**。原因：`wawoff2` 的 Emscripten 模組只在 Node 環境匯出，瀏覽器打包後解壓承諾永遠不解決（2026-11-01 在 Chromium 實測卡死）。被否決：wawoff2。
3. **不用 `subset-font`／`fontverter`**（原型用）：主程式用 Node 的 `fs`／`Buffer`。改成自包薄層，wasm 由 Vite 打成獨立檔案並延遲載入。
4. **Word 版不內嵌字型**（使用者 2026-10-30 已決定，見原型驗證結果第 7 點）。
5. **標題不得孤零零留在頁尾**（PDF 先確認下一區塊放得下；Word 用 keepNext）；表格跨頁時表頭重複（PDF 與 Word 皆是）。
6. 範本的表格列固定單行高度，**儲存格文字不換行**（題項名稱要短）；原型的 Word 排版限制（固定行高等）沿用。

## 驗證

- 單元測試（`src/export/export.test.ts`）：模型、換行、xlsx 讀回、docx 結構、批次 zip、字型管線。
- 視覺檢查（`src/export/visual.test.ts`）：把 PDF 渲染成圖，子集化版與完整字型版逐頁比墨跡（差 0.5% 內）與像素差異（0.05% 內）；標題孤兒檢查。
- 瀏覽器端對端（`tests/e2e/export.spec.ts`，Chromium）：真實下載字型與 wasm、解壓、子集化、輸出 PDF／Word／xlsx／zip，並確認 Service Worker 快取後第二次不再連網。
- 本機 Excel／Word（Windows）實際開啟輸出檔：xlsx 的值、數字格式 `0.0`、列數正確；docx 班級總表為橫式 2 頁、個人回饋單 2 頁（與 PDF 頁數相同）。

## 未驗證（不要當成已驗證）

- Safari／iOS、手機等級 CPU、Word for Mac（PingFang TC）、LibreOffice、Google 文件。
- 罕用字（超出基本多文種平面）、簡體、假名、超長留言；其他範本版面。
- 字型檔來自本機 Windows 內建版（2.04，name 表標「non-release」），內容未改；如要換成官方釋出版，執行 `node scripts/build-font.mjs <來源 ttf>`。
- 圖表：圖片區塊只接收 PNG，圖表繪製（自製 SVG → PNG）尚未做。

## 二、設計重點（細節見 DESIGN.md 5.31）

- **六項導覽（錨點 g1～g6）**：共同前置：建立回應試算表／做法一：直接讀取 Google 試算表／做法二：下載檔案再匯入／Google 表單怎麼設計／範本表單／示範資料。
- **三裝置版面**：手機沒有左欄，頁首下方一顆「本頁目錄」折疊鈕；平板左欄 200 寬、桌機左欄 240 寬（sticky，目前項目用強調淡底＋左側 3px 線＋粗體）；平板以下兩個做法上下排，**桌機兩個做法並排**（一眼比較「適合誰」）。
- **做法卡**：標籤（做法一／二）→ 標題 → 「適合：…」一行 → 編號步驟（每張從 1 開始）→ 補充小字。做法一多一個折疊「遇到問題」（三種情況＋選帳號示意圖＋「改用做法二」按鈕）。
- **步驟用字**：Google 畫面名稱全部逐字取自[核對紀錄](../design/Google介面核對紀錄.md)（「發布」「發布表單」「回覆」「連結至試算表」「選取回應目標位置」「建立新試算表」「建立」「表單回覆 1」「檔案」›「下載」›「Microsoft Excel (.xlsx)」等）。多層選單用「選單路徑」小標（`.mp`）。
- **「適合：…」的措辭**取自草案的「我的建議」，**沒在手機或平板實機走過**；做法一寫「桌機、願意登入 Google 的人。需要連網，瀏覽器不能擋彈出視窗。」，做法二寫「手機、平板、Safari、Firefox、不想登入，或學校帳號被擋的人。」。
- **題型對照**改用核對後名稱（簡答、選擇題、核取方塊、線性刻度、詳答、單選方格），移除「待核對」，改寫核對日期與「題型以題目右上角的下拉選單為準」。
- 做法二寫「只選 .xlsx 或 .csv，.ods、.pdf、.html 讀不了」，**刻意不提 .tsv**：核對紀錄只確認選單有它，本程式是否讀它沒有在這份稿查證（實作前請問施工對話或查匯入程式）。

## 三、被否決的方案與原因

| 方案 | 否決原因 |
|---|---|
| 手機導覽用「橫向捲動的籌碼列」 | 規範 3 不得橫向捲動（只有表格與程式碼例外）；六個長名稱在 390 寬放不下；容易誤觸。 |
| 手機導覽用固定在螢幕底部的「目錄」浮動鈕 | 會壓到頁面底部內容與系統手勢區，且教學頁本身沒有底部操作列，為它另造一個固定元件不划算。 |
| 手機導覽直接把六個連結全部攤開在頁首 | 六個 48 高連結約佔 380px，把第一張卡擠到第二屏；折疊目錄只佔 48px。 |
| 平板兩個做法並排 | 內容欄只有約 540 寬，每欄約 260，選單路徑與長步驟會嚴重換行；桌機才有足夠寬度。 |
| 兩個做法用分頁籤（tab）切換 | 一次只看得到一條，無法比較「適合誰」，列印、搜尋、無障礙都較差；與裁示「並列」不符。 |
| 兩個做法的步驟編號接續（做法二從 6 開始） | 兩者是二選一，不是先後；接續編號會讓人以為兩個都要做。 |
| 「適合誰」做成比較表 | 使用者裁示是每張卡開頭一句；多一張表是未被要求的內容。 |
| 故障排除保留成獨立卡放最後 | 使用者已裁示降為折疊；放在它發生的地方（做法一底下）才讀得到。 |
| 折疊預設展開 | 正常流程的人用不到，會把做法一拉長一倍、做法二被推遠。預設收合，摘要有一行副標說明裡面有什麼。 |
| 折疊用「左側色邊的圓角卡片」 | 規範 1 與設計方法的「避免俗套」；沿用既有 `.fold` 外框樣式即可。 |

# 對外文件預覽核對（SUR-09）

- 日期：2026-11-07（台北時間）
- 狀態：已實作，分支 `fix-sur09-external-docs`（待審 PR，尚未發布）
- 來源：[問卷匯入與統計主流程稽核 SUR-09](../analysis/2026-11-03-問卷匯入與統計主流程稽核-ChatGPT.md)

## 實測做了什麼

用虛構資料（三位學生；採用、隱藏、未審、改寫各一則留言；留言含名單內姓名與名單外人名；每位都有老師評語），把兩份內建個人回饋單範本 × 學生版／家長版實際產生 Word 與 PDF，再解析**檔案裡的文字**（Word 讀 `w:t`、頁首頁尾與 `dc:title`；PDF 用 pdfjs 取文字與 Title）比對。測試在 `src/app/output-check.test.ts`。

## 結果

1. 沒有個別版本時，檔案文字與文件模型（`DocModel`）完全相同；模型裡範本固定字以外的文字，正好是預覽列出的留言與老師的話。隱藏、未審、改寫前的原文都不在檔案裡，名單內姓名在留言裡已換成「某同學」。
2. 找到三個預覽沒涵蓋的地方（已修）：
   - 範本「個別版本」（單一學生覆寫）改過的文字與 `{老師評語}` 等變數會印進檔案，但預覽看不到，確認簽章也不含它們。
   - 預覽確認後換輸出範本或改個別版本，不會要求重新預覽。
   - 自訂範本用了 `{全班名次}` 時，學生版與家長版會印出名次（與「回饋單不顯示名次」不符）。
3. 老師評語裡名單上其他同學的姓名**不會**遮蔽（留言會），預覽原本也沒有標示。

## 決定（我替使用者決定的事，可改回）

- **預覽與下載用同一條編譯路徑**：預覽打開時用和下載相同的範本與個別版本編出每位學生的文件，把「全部文字」當簽章；產生 Word、PDF、批次 zip、瀏覽器列印前再編一次比對，不同就擋下並請老師重新預覽。純函式在 `src/app/output-check.ts`（`docTexts`、`docSignature`、`overrideTexts`、`teacherCommentHits`）。
- **預覽多列「個別版本」多出的文字**：套個別版本的文件減去沒套的文件（多重集合差），列在該學生下方。
- **老師的話只標示、不改字**：標出名單上其他人的姓名（不標本人）與可能的名單外人名，加「這段文字的姓名不會自動遮蔽」標籤。沒有自動遮蔽，因為自動替換會連本人姓名一起換掉，也會改動老師刻意寫的字。
- **`{全班名次}` 對外版一律空白**：和摘要數字列的名次卡一致（只給教師版）。
- 介面改動只在既有預覽視窗加一段清單與一個標籤，沿用既有元件（`plain-list`、`mark.pn`、`tag warn`），屬小改，未另走設計員。

## 待使用者決定

- 老師的話裡名單上其他同學的姓名，要不要比照留言自動換成「某同學」（目前只標示）。

## 沒驗到的

- 「預覽後內容變動 → 下載被擋 → 重新預覽」這條路徑只有單元測試與型別保證，沒有 e2e；e2e 只驗了正常預覽後單人 PDF 與批次 zip 能下載（核對沒有誤擋）。
- 班級總表（教師用）、意見調查與票選報告不在學生／家長預覽範圍，未改。

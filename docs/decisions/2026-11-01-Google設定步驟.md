## 步驟與實際介面名稱（2026-11-01 核對）

1. **建立專案**：開 `https://console.cloud.google.com/projectcreate`（頁名「新增專案」）。「專案名稱」填 `survey-feedback-helper`（專案 ID 自動同名）、「父項資源」維持「無組織」，按「建立」。頁面會提示「您的配額還可供建立 5 projects」。
2. **確認未綁帳單**：左側選單「帳單」→「已連結帳戶」，應顯示「這項專案沒有帳單帳戶」，並有「連結帳單帳戶」「管理帳單帳戶」兩個按鈕——**不要按「連結帳單帳戶」**。全帳號的「帳單帳戶管理」→「您的專案」分頁也應顯示該專案「計費功能已停用」（舊專案 Gemini API、lunch-helper、Teacher Quick Notes 同樣是此狀態）。
3. **啟用 API**：「API 和服務」→「程式庫」，搜尋或直接開 `…/apis/library/drive.googleapis.com`、`picker.googleapis.com`、`sheets.googleapis.com`，各按一次「啟用」。啟用後「API 和服務」→「已啟用的 API 和服務」會列出三者。清單裡另有約 23 項 Google 對新專案預設啟用的服務（BigQuery、Cloud Logging 等），是預設值、免費額度內也無帳單，**不需要也不要去動**。
4. **OAuth 同意畫面**（現稱「Google Auth Platform」，左側選單：總覽、品牌、目標對象、用戶端、資料存取權、驗證中心、設定）：
   1. 「總覽」→「開始」→ 精靈四步：①「應用程式資訊」填「應用程式名稱」`問卷回饋小幫手`、「使用者支援電子郵件」選 `derliang@gmail.com`；②「目標對象」選「外部」（私人 Gmail 沒有「內部」可用）；③「聯絡資訊」填電子郵件；④「完成」勾「我同意《Google API 服務：使用者資料政策》」→「繼續」→「建立」。
   2. 「資料存取權」→「新增或移除範圍」，右側「更新所選範圍」面板的「篩選條件」輸入 `auth/drive.file`，勾「Google Drive API／`…/auth/drive.file`」→「更新」→ 頁面底部按「Save」（按鈕當日顯示英文）。結果只出現在「您的非機密範圍」。
   3. 「目標對象」→ 捲到「測試使用者」→「Add users」（當日顯示英文）→ 輸入 `derliang@gmail.com`、Enter →「儲存」。**此頁要實際看到清單出現該信箱才算成功**（第一次按「儲存」沒有生效，重按後才出現，並顯示「1 位使用者」）。
5. **建立 OAuth 用戶端 ID**：「Google Auth Platform」→「用戶端」→「建立用戶端」（網址 `…/auth/clients/create`）。「應用程式類型」選「網頁應用程式」，「名稱」填 `survey-feedback-helper-web`；「已授權的 JavaScript 來源」按「新增 URI」兩次，填 `https://derliang.github.io` 與 `http://localhost:5173`；「已授權的重新導向 URI」不填；不勾「讓 AI 代理使用這個用戶端」；按「建立」。完成視窗「OAuth 用戶端已建立」會顯示「用戶端 ID」與「用戶端密碼」，按「確定」關閉。頁面提示「設定可能需要 5 分鐘至數小時才會生效」。
6. **建立 API 金鑰**：「API 和服務」→「憑證」→「建立憑證」→「API 金鑰」（或開 `…/apis/credentials/key`，頁名「建立 API 金鑰」）。「名稱」填 `survey-feedback-helper-browser-key`；「選取 API 限制」下拉的篩選條件輸入 `Google` 後 Enter，勾「Google Drive API」「Google Picker API」「Google Sheets API」→「確定」（會顯示「3 個 API」）；「應用程式限制」選「網站」→「Add」（當日顯示英文）→「網站」欄貼 `https://derliang.github.io/survey-feedback-helper/*` →「完成」，再 Add 一次填 `http://localhost:5173/*` →「完成」；按「建立」。完成視窗「已建立 API 金鑰」顯示金鑰值，按「繼續」。**注意**：在控制台輸入網址時，游標若不在輸入欄，字元 `/` 會被當成「搜尋」快速鍵搶走輸入；請先點進欄位再打字。
7. 驗證：「憑證」頁應有一把 API 金鑰（限制欄顯示「HTTP 參照網址, 3 個 API」）與一個網頁應用程式用戶端。

## 發布狀態的利弊（尚未決定，目前維持「測試中」）

- **測試中（現況）**：只有「測試使用者」清單（上限 100 人）能登入；登入時會看到「Google 尚未驗證這個應用程式」警告，需按「進階」→「前往…（不安全）」；對 `drive.file` 這類非機密範圍沒有七天重新授權的問題（網頁權杖流程本來就不發 refresh token）。優點：不對外、零審查。缺點：別的老師用不了，要一個一個加進測試使用者。
- **發布到「正式版」**：任何 Google 帳號都能登入。`drive.file` 是非機密範圍，**不必送 Google 敏感範圍審查**；但若要拿掉「未驗證」警告，需完成「品牌」驗證（應用程式首頁、隱私權政策連結、網域驗證），這些要有可公開的頁面。
- 建議（**我的建議，待使用者裁示**）：開發與自測期間維持「測試中」；要開放給其他老師前，先把隱私權政策頁放到 Pages 上，再於「目標對象」按「發布應用程式」並走品牌驗證。

## 如何撤銷與輪替

- **輪替 API 金鑰**：「憑證」→ 該金鑰「顯示金鑰」旁選單 →「複製金鑰」建立新的前，先到金鑰詳細頁「重新產生金鑰」或另建一把（相同限制），把新值更新到 `.env.local`（含發布那台電腦）、重新 `npm run release -- --yes`，確認正式站可用後再刪舊金鑰。
- **撤銷 / 停用**：刪除 API 金鑰（「憑證」頁勾選→「刪除」）、刪除或停用 OAuth 用戶端（「Google Auth Platform」→「用戶端」→ 該用戶端的「停用」或刪除圖示），網站上的 Google 功能會立刻失效並顯示「目前沒有開放 Google 登入」的友善說明（缺設定即停用）。
- **使用者自己撤銷授權**：Google 帳戶 →「安全性」→「第三方應用程式和服務」（以 Google 當日介面為準）找到「問卷回饋小幫手」移除存取。
- **整個專案下架**：「管理資源」選專案 →「刪除」（30 天內可還原）。
- 金鑰一旦出現在不該出現的地方（例如被貼到公開 issue），視同外洩：立刻輪替；它已限網址與三個 API，影響面有限，仍須輪替。

## 被否決或沒做的選項

- **內部（Internal）使用者類型**：私人 Gmail 沒有 Workspace 組織，無此選項。
- **帳單與 Google Cloud 免費試用**：不做，違反硬規則 4。
- **用戶端密碼放進前端**：網頁權杖流程不需要，沒有安全用途，不存。
- **把值寫進 `vite.config.ts` 或 commit `.env`**：否決，維持環境變數注入。
- **`http://127.0.0.1:5173` 另列**：沒加，開發一律用 `localhost`；改用 127.0.0.1 會被 Google 拒絕，需另補來源與參照網址。
- **Picker 是否需要 App ID 等實測問題**：留給 `google-v04` 的實測，不在本文件範圍。

### CPU 降速效能（Chromium、`node scripts/perf-throttle.mjs 1 4 6`）

單位毫秒，桌機 Chromium 加 CDP 降速（1x＝這台桌機，4x≈中階手機，6x≈低階手機）。**這台同時有其他對話在跑，6x 的數字起伏很大，請看範圍**；網路時間不含（下載另計）。

| 階段 | 1x | 4x | 6x |
|---|---|---|---|
| WOFF2 解壓（優化前，每次輸出都要做） | 180～200 | 740～920 | 1100～4400 |
| 讀「解壓後 TTF 快取」（優化後，第二次起） | 8 | 25～30 | 40～200 |
| HarfBuzz wasm 初始化 | 3 | 8～13 | 24～42 |
| 子集化一個字重 | 22～24 | 100～140 | 170～1080 |
| 單份 PDF（個人回饋單） | 115～150 | 420～510 | 650～2600 |
| 35 份批次 PDF（每份之間讓出執行緒） | 550～650 | 2400～4000 | 3700～7400 |
| 最長一次卡住主執行緒 | 60～110 | 350～440 | 560～2200 |

優化前後（`loadFonts`，第一次含解壓 → 清掉記憶體後第二次）：1x 143～166 → 38～41；4x 933～962 → 166～356；6x 974～1694 → 113～121（另一輪 6x 解壓曾到 4.4 秒）。做法：解壓後的 TTF（約 11.4 MB）存進 Cache Storage（`sfh-ttf-v1`，以 WOFF2 大小當版本）；沒有快取、不支援或配額不足時退回照常解壓。取捨：多用 11.4 MB 瀏覽器儲存空間（不含問卷資料，硬規則 6 不受影響）。

**沒做 Web Worker**：批次已每份讓出執行緒，介面不會整段凍結，單次卡頓在 4x 約 0.4 秒；等實機（下方 B 項）量到明顯卡頓再做，做的話前後比較看「最長一次卡住主執行緒」。

## 二、Word 字型退讓清單（`src/fonts/word-fonts.ts` 檢查結果）

docx 只能指定一個字型名稱，找不到時由開啟的程式自行取代。檢查結論：現有清單（Windows：Microsoft JhengHei；Mac：PingFang TC）對 Word 夠用，**不再加內嵌**（原型已證實 Microsoft 365 不認內嵌子集字型）。

| 開啟環境 | 實際會用到的字型 | 狀態 |
|---|---|---|
| Word for Windows | 微軟正黑體 | 已驗證可開、頁數與 PDF 相同 |
| LibreOffice（Windows） | 微軟正黑體 | 本次已驗證 |
| Word for Mac | 預設輸出為 Windows 字型時，Word 自動取代為系統字型；`wordFontFor('mac')` 指定 PingFang TC | **需實機（A1）** |
| Google 文件、Word 網頁版、手機 Word | 不一定有微軟正黑體，會取代為預設中文字型 | **需實機（A2）**；換行位置可能與 PDF 差一兩字 |

說明文字 `WORD_FONT_NOTE` 目前只說 Windows／Mac，建議加一句「用 Google 文件或手機開啟時，字型會由該程式決定，需要完全一致請用 PDF」——**待 A2 實測後再定稿**，現在不改（避免寫沒驗證過的行為）。

## 三、需使用者實機驗證的項目

> 每項不超過 5 步。測試檔產生方式（在這台電腦或任一台裝好 Node 的電腦做一次）：`npm ci` → `EXPORT_DUMP_DIR=<資料夾> npx vitest run src/export/export.test.ts`（PowerShell：`$env:EXPORT_DUMP_DIR="D:\temp\out"; npx vitest run src/export/export.test.ts`），會得到 xlsx、docx、PDF 與批次 zip 共 8 個虛構測試檔。**檔案不要放進 repo**（`.gitignore` 已擋）。

### A. 開啟輸出檔

**A1 Word for Mac（需要 Mac）**
1. 把 `個人回饋單.docx`、`班級總表.docx`、`罕用字超長留言.docx` 拷到 Mac。
2. 用 Word 開啟，看標題、表格、頁碼「第 N 頁，共 M 頁」是否正常，中文是否有缺字（方框）。
3. 用 Word「檔案 > 另存為 > PDF」，頁數是否與同名 PDF 的頁數相同（個人回饋單 2 頁、班級總表 2 頁、罕用字 3 頁）。
4. 在 `罕用字超長留言.docx` 看「𠮷𩸽」、簡體、韓文、表情是否顯示（預期會用備援字型補上）。
5. 回報：通過／哪一項不對（附截圖）。

**A2 Google 文件**
1. 登入 Google 雲端硬碟，把同樣三個 docx 拖進去。
2. 對檔案按右鍵「開啟方式 > Google 文件」。
3. 看表格、頁碼、字型（右上角字型名稱）、有沒有缺字。
4. 在文件選「檔案 > 下載 > PDF 文件」，比頁數。
5. 回報：字型被換成什麼、換行位置與 PDF 差幾個字。

### B. 瀏覽器（輸出頁完成、上線後才能做）

> 目前沒有輸出頁（todo「輸出頁接線」），Safari 與手機只能等輸出頁接上後驗證；做法預先寫好如下。

**B1 Safari（Mac）與 iOS Safari 16.4 以上**
1. 開啟正式站，進輸出頁，載入虛構資料。
2. 輸出「個人回饋單 PDF」，數秒數（秒錶即可）：第一次與第二次各一次。
3. 輸出「批次 zip（35 份）」，看進度是否持續前進、畫面有沒有凍住。
4. 關掉分頁重開再輸出一次：第二次是否明顯變快（快取生效）。
5. 回報：兩次秒數、是否出現錯誤文字。

**B2 手機與平板的下載／分享**
1. 在 iPhone／iPad Safari、Android Chrome 各輸出一份 PDF 與一份 docx。
2. 看是否能存到「檔案」／下載，或用分享表單送出。
3. 用手機的檔案預覽打開 PDF，看中文是否缺字。
4. 回報：哪個瀏覽器不能存檔、秒數。

**B3 手機實機效能（取代降速模擬）**
1. 在最舊或最慢的一支手機上，輸出批次 zip（35 份）。
2. 記錄總秒數與「畫面卡住超過 1 秒」的次數。
3. 回報給施工對話；若卡頓明顯，下一步做 Web Worker。

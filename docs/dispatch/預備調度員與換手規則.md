# 預備調度員與換手規則（使用者 2026-11-07 裁示）

> 給下一任調度員：這份規則要**一代一代交接下去**，換手時把本檔路徑寫進接手令，並確認新調度員讀過。通用流程見技能 `dl-dispatcher` 的〈調度員換手〉（`references/quota-and-context.md`）；**本檔是使用者對本專案的補充裁示，與技能衝突時以本檔為準**。

## 使用者原話（2026-11-07）

「你先開啟預備用的空白對話五個，這五個專門用來交接調度員的工作，當我指示交接時，就請妳交接對話給空白的對話，讓新的對話成為新的調度員，你本身就收尾跟封存自己。請把這規則也交接下去。」

## 規則

1. **隨時保持五個「預備調度員」空白對話**：獨立 worktree、已脫離（`detach_session`，不掛在調度員底下）、標題 `問卷⏸預備調度員 N（空白待命，等交接）`、Sonnet medium。它們**只用來接手調度員的工作**，不拿去當一般工作對話用（一般工作用「空白待命 J～M」那批，或另開）。用掉一個，新調度員接手後要補開，維持五個。
2. **換手觸發**：使用者說「交接」「換調度員」之類，或 context 達技能規定的門檻。使用者原話授權換手與封存時**直接做，不再問**。
3. **交接流程**（由舊調度員執行）：
   1. 停接新工作，把交接檔寫進專案（`docs/dispatch/調度員換手交接.md`：現況、進行中對話與 session id、空白待命與預備調度員 session id、待審 PR、待裁決事項、下一步、本檔路徑）並 push。
   2. 從五個預備調度員挑一個 context 最小的，用 `SendMessage` 傳完整接手令（第一步載入 `dl-dispatcher`；讀交接檔與本檔；舊調度員 session id；新調度員接手後要做的事見第 4 點），再 `set_session_title` 改成「問卷🔄調度員」。
   3. 通知所有進行中對話「之後回報新調度員 session id」（可由新調度員通知，但要確認每個都回覆收到）。
   4. 舊調度員驗收四項證據（見技能〈換手驗收〉）：新調度員在執行中且已讀交接檔、進行中對話都已回覆、舊調度員已脫離子對話。
4. **新調度員接手後要做的事**：①讀交接檔與本檔，核對 `list_sessions`；②通知所有進行中對話新的 session id；③**補開預備調度員，補回五個**（`start_session` 被 Remote Control 拒絕時，在回報裡告訴使用者「回桌面 app 時補開」，不卡住）；④把本檔規則原封不動交接給下一任；⑤接手後對使用者只回報一行摘要。
5. **舊調度員自己收尾並封存自己**（使用者裁示，取代技能「新調度員封存舊的」的預設）：舊調度員在上述驗收通過後，**最後一步由自己 `archive_session` 封存自己**；做之前先確認：已 push（含交接檔）、無背景工作、子對話已脫離、自己的最後一則回報已送出。若 app 拒絕封存自己，改請新調度員用 `archive_session` 封存舊的，並告訴使用者被拒原因。不要等使用者再下指令。
6. 舊調度員在封存前若被使用者找：只回一行「調度員已換成〔新調度員連結〕，它正在處理」，不再派工，不要求使用者去對新調度員下指令。

## 建議（待技能員處理，我沒有改技能）

技能 `dl-dispatcher` 〈調度員換手〉目前寫「舊調度員不封存自己、由新調度員封存」，與本裁示不同；建議交給技能員改成「舊調度員驗收後自己封存，被拒才由新調度員封存」，並加入「保持五個預備調度員」。

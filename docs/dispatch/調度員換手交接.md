## 使用者常態規則（務必遵守）
- 「全部派出去」永久有效：每條 todo 都要有 session（待命也算），開工順序由調度員決定，不再逐項問；回答「都派了嗎」前先逐行對照 `todo.md`。
- 選擇題一律用 AskUserQuestion 問題卡；繁體中文；台北時間。
- 對話標題反映真實狀態：進行中用「進行中｜…」，待命用「待命｜…」；狀態變了當下就改，但標題仍正確的不要亂改。
- 已完工且 PR 已併的對話要封存。違規時使用者說「登記違規」→ 寫進 `~/.claude/skills/共同記憶/RULE_VIOLATIONS.md`。
- 發布常態授權：`main` 有審過的進展且 `npm run ci` 全綠，就發布（不必等全部完成）。

## 例行流程
- 審 PR：`git fetch origin pull/N/head:prN`、`git worktree add ../sfh-prN prN`、merge origin/main（`todo.md` 衝突常見，保留兩邊／[x] 版本）、`npm ci`、`PORT=46xx npm run ci`、確認沒有 xlsx/csv/docx/pdf、`gh pr merge N --squash`、`git pull`、移除 worktree、封存對話。合併後若 GitHub 一度回「not mergeable」是在重算，等幾秒重試。
- 發布：先開小 PR 升 `package.json`、`package-lock.json`（第 3、9 行）與 `CHANGELOG.md`（release 腳本拒絕已存在的 tag），併入後在乾淨的 main 跑 `npm ci` 再 `PORT=4500 npm run release -- --yes`，回報 gh-pages SHA；Pages 偶爾卡住，可用 `gh api -X POST repos/derliang/survey-feedback-helper/pages/builds` 重觸發，並以正式站 `version.json` 確認。
- 純文件可直接 push main。
